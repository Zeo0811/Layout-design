# 设计文档：公众号「十字路口绿」新样式（编辑器预览）

- 日期：2026-05-21
- 范围：仅 `index.html` 模板编辑器 + 预览（不含 Chrome 扩展集成）
- 设计来源：Figma「十字路口」文件 `jGGJdksNipepgwsR115paX`，node `0:1`

## 1. 目标

在排版编辑器 `index.html` 中**新增一个模板「十字路口绿」**，忠实还原 Figma 上的新版公众号排版样式。其中标题 H1–H6 因使用非系统字体「可画大丰收体」，采用 **canvas 渲染成 PNG 图片**的方式实现；其余组件用纯 CSS token 表达。本轮只需在编辑器里把效果**预览**出来。

## 2. 关键约束与背景

- **微信公众号会剥离 `@font-face` 和大部分自定义字体声明。** 标题字体「可画大丰收体」和正文备选 OPPOSans / HarmonyOS Sans SC 在读者端都会回退到系统字体（iOS 多为苹方）。
- 因此「可画大丰收体」标题要忠实还原，唯一可行路径是**把标题文字画成图片**（canvas → base64 PNG → `<img>`）。SVG + 内嵌字体、实时文字 + @font-face 均不可行（前者被微信剥离，后者回退）。
- 编辑器 `index.html` 当前已有：
  - 主样式对象 `S = {...}`（现行默认：橄榄绿 `#407600` 体系）
  - 模板系统：每个模板 = 一组 token 的 CSS 字符串，逐 CSS 属性可编辑（`PROP_ENUMS` / `SEED_PROPS` / `parseCssStr` 等）
- **模板系统存的是 CSS 字符串，无法表达"标题图"**。故标题图渲染须作为预览中的独立逻辑，不走通用 CSS 属性编辑器。

## 4. 架构与组件划分

### 4.1 字体落位（新增）
- 在项目内新建 `assets/fonts/`，拷入：
  - `可画大丰收SC.ttf`（源：`~/Downloads/可画大丰收SC.ttf`，约 14MB）
  - `HarmonyOS_Sans_SC_{Light,Regular,Medium,Bold}.ttf`（源：`~/Downloads/HarmonyOS_Sans_SC.zip`，按需取 4 个字重）
- `index.html` 用 `FontFace` 或 `@font-face` 加载这些字体，供预览渲染。
- 职责：让预览能用真实字体绘制；不依赖外网。

### 4.2 标题图渲染器 `renderHeadingImage(text, level)`（新增，预览专用）
- 输入：标题文字、级别（1–6）
- 行为：
  1. 确保大丰收字体已 `await document.fonts.ready`
  2. 创建 2x（retina）canvas，按级别字号绘制绿 `#327847` 文字，左对齐，透明底
  3. 超出正文宽度时**自动按字符换行**（多行布局，行高与字号成比例）
  4. `canvas.toDataURL('image/png')` → 返回 `<img src="data:..." style="width:<显示宽>;...">`
- 各级别参数（字号、行高、上下间距、颜色）由模板定义集中持有，**本轮写死**，不暴露到通用 CSS 属性编辑器。
- 依赖：4.1 的字体加载。
- 边界清晰性：纯函数式，输入文字+级别 → 输出 `<img>` HTML 串，可独立测试（给定文字与级别，断言产出 `<img>` 且 data URI 非空、宽度符合预期）。

### 4.3 新模板定义「十字路口绿」（新增）
- 一套完整 token 值（CSS 字符串），覆盖：正文 `p`/行内格式、引言 `blockquote_*`、列表 `ul/ol/li_*`、图片 `img_*`、callout `callout_*`、折叠 `toggle_*`、代码 `code_*`、分隔线 `hr`、脚注 `footnotes_*`/`footnote_*`、嵌入 `embed_*`、表格 `table_*`、参考资料。
- 颜色/字号/间距按第 3 节落值。
- H1–H6 在该模板下**不走 CSS token**，而是标记为"图片渲染"，预览时调用 4.2 的渲染器。
- 接入模板系统：作为可切换模板出现（保留现有 `#407600` 默认）。

### 4.4 预览渲染改造（index.html 内）
- 现有 demo 预览（`blocks` 数组 + `card()`）与模板预览面板（`tpl-preview`）需识别：当前模板的 H1–H6 是"图片型"时，调用 `renderHeadingImage` 输出 `<img>`，而非套 CSS 文本。
- 正文等非标题组件照常套对应 token。

## 6. 错误处理
- 字体加载失败：`renderHeadingImage` 应 `await document.fonts.ready` 并对目标字体做存在性检查；失败时退化为系统字体绘制并在预览中给出可见提示（不静默出错）。
- canvas 不可用 / `toDataURL` 失败：退化为普通绿色文本标题，保证预览不空白。
- 超长标题：换行算法须有最大行数保护，避免图片过高。

## 7. 测试策略
- `renderHeadingImage` 单元验证：给定（文字、级别）→ 断言返回 `<img>`、含 `data:image/png`、显示宽度随级别变化、超长文字产生多行（高度增加）。
- 预览快照：切到「十字路口绿」模板，肉眼核对 H1–H6 为大丰收图、正文/引言/列表/图注/callout 等配色与 Figma 一致。
- 回归：现有默认 `#407600` 模板与其余模板预览不受影响。
